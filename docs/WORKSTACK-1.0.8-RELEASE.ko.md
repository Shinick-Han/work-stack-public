# Work Stack 1.0.8 설치 후보 안내

1.0.8은 2026-09-07 공개용 수동 설치 시험 릴리스(pre-release)로 준비했다. 최신 설치·기존 설치 업그레이드 절차는 [1.0.8 설치 안내](WORKSTACK-1.0.8-INSTALL-UPGRADE.ko.md)를 따른다. 아래는 저장 형식 변경 설명이다. 안정 버전 자동 업데이트는 전체 릴리스 게이트 완료 전까지 1.0.7을 유지한다.

기존 화면과 조작 방법은 [1.0.7 설치·사용 안내서](WORKSTACK_INSTALL_OPERATION_GUIDE.ko.md)를 참고한다. 그 문서의 설치본 관찰과 공개 배포 상태는 당시 기록이다. 새 설치 파일명은 `WorkStack-Setup-1.0.8.ps1`이며, 함께 받은 `.sha256`을 `scripts/windows/Test-WorkStackSetup.ps1`로 확인한 뒤 실행한다.

## 저장 형식과 데이터 보존

1.0.8은 보고서 저장을 위한 `reports.json`을 추가하는 collection schema 5를 사용한다. 기존 schema 3의 아홉 문서는 업그레이드 전에 검증한 뒤 하나의 저널로 전환한다. schema 4는 별도의 실험적 저장 방식이며, schema 5를 뜻하지 않는다.

업그레이드 전에 기존 런타임으로 선택한 데이터 저장소의 백업을 만들고 검증한다. 첫 실행 때 생성되는 `.workstack-migration-backups`의 이전 버전 ZIP도 보관한다. 이미 알려진 다른 로컬 프로필은 직접 열기 전까지 자동 전환된 것으로 간주하지 않는다.

실행 파일을 1.0.7로 되돌리는 것만으로 데이터가 schema 3으로 돌아가지는 않는다. 복구가 필요하면 보관한 이전 런타임과 검증된 schema 3 백업을 사용해 별도의 빈 경로에 복원하고 확인한 뒤 프로필을 전환한다. 최신 런타임의 복원 경로는 이전 백업도 schema 5로 업그레이드하므로 다운그레이드 도구로 사용하지 않는다.

## 확인할 항목

- 실행 파일·설치 패키지의 제품 버전이 모두 1.0.8이며, 검증한 소스 및 프런트엔드 산출물과 설치 파일이 일치한다.
- 활성 로컬 프로필의 경로와 workspace UID가 유지되고 health가 ready이다.
- schema 5와 `reports.json`이 존재하고 이전 버전 백업의 검증이 성공한다.
- 기존 Task·Objective·노트·업무 기록이 보존되고 동기화 상태가 정상이다.

`storage_status.file_count`는 의미상 문서 수로 schema 5에서 9이다. 백업의 물리적 문서는 메타데이터를 포함해 10개이므로 두 수치가 다른 것은 정상이다.

보고서 정식 저장 화면과 원격 설치 UI는 별도 후속 기능이다. 저장 기반을 포함했다는 사실만으로 그 기능이 완료된 것으로 표시하지 않는다.
