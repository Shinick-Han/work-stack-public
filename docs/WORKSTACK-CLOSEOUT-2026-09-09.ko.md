# Work Stack 제품 경계와 라운드 마감 — 2026-09-09

## 제품의 목적

Work Stack은 Task에 필요한 정보와 근거를 기록하고, 연결된 지식 저장소에서 맥락을 가져와 검토하며, 작업 단계·진행 상황·다음 행동을 관리하는 도구다. 사람과 외부 Agent는 클라이언트로 사용할 수 있다. Agent의 실행 환경이나 범용 오케스트레이터를 제품의 필수 구성으로 삼지 않는다.

Work Stack은 자신의 저장소 일관성, 단일 writer, 접근 범위, 입력 계약, 안전한 화면 표시, 사용자가 확정하는 업무 변경을 책임진다. 외부 RAG의 모든 프롬프트 주입을 탐지하거나 출력에서 지시문을 완전히 제거하는 책임까지 확장하지 않는다. 외부 문서는 데이터로 취급하며 문서 속 지시를 실행하지 않는다. 외부 Agent에 부여한 실행 권한과 격리는 해당 harness의 책임이다.

## 이번에 확정한 변경

- 일반 CLI의 `worklog latest-checkpoint`가 Task Resume 화면과 같은 최신 체크포인트 사실을 JSON 또는 Markdown으로 반환한다.
- 로컬 읽기와 실행 중인 owner를 통한 읽기를 지원하며, 조회는 업무 데이터를 변경하지 않는다.
- 기존 Agent context 계약은 유지한다. 체크포인트 계약과 구현의 분리는 범용 클라이언트 지원이며 Agent 실행 기능 추가가 아니다.
- 독립 검수에서 발견한 비정상 Unicode 처리 결함을 수정했다. 수정 검증 26개와 CLI 검증 60개가 통과했다.
- 구조 검사 538개 production 파일이 통과했으며 기술 부채 허용치를 늘리지 않았다.
- 실제 임시 owner와 데스크톱/390px 브라우저에서 GUI·CLI 결과 일치와 조회 전후 11개 JSON 파일 불변을 확인했다.
- 마감 설치 시험에서 설치 프로그램이 정상 v6 저장소를 거부하는 허용 목록 누락을 발견해 수정했다. v6 선택·백업 경로와 잘못된 baseline 거부를 회귀 시험에 추가했다. 저장소를 이전 형식으로 변환하거나 authority 검사를 건너뛰지 않는다.

## 후속으로 남긴 항목

OpenDocuments는 고정한 upstream으로 설치했고 비민감 합성 문서의 실제 검색, 한국어 날짜 변경, workspace 격리를 검증했다. Work Stack을 통한 요청 → 검색 → 검토 → 저장 왕복 시험은 준비만 되었으며 실행 완료로 간주하지 않는다.

다음 라운드는 위 왕복 흐름의 사용자 효용을 우선 확인한다. 근거 갱신·삭제·접근 취소, 고객 환경 검증, 자동 업데이트 실측은 각각 별도 완료 조건을 유지한다. 외부 RAG가 문서 속 지시문을 인용한 관찰은 Work Stack 결함이나 출시 차단 조건으로 승격하지 않는다.

## 배포 경계

이번 마감은 1.0.13 소스 스냅샷과 로컬 설치본 갱신이다. 공개 소스 push는 GitHub Release 게시나 회사 환경의 자동 업데이트 성공을 의미하지 않는다. 새 Release를 게시하기 전까지 기존 공개 바이너리 릴리스가 유지된다.

Smart App Control이 서명되지 않은 네이티브 호스트를 차단하는 환경에서는, 별도로 확인한 서명된 번들 Python 런타임으로 같은 데스크톱 진입점을 실행하는 로컬 바로가기를 임시로 사용할 수 있다. 이는 제품 코드 서명이나 모든 종속 파일의 실행 허용을 보장하지 않는다. SAC 설정은 변경하지 않으며, 다음 설치가 기본 바로가기를 다시 만들 수 있다.
